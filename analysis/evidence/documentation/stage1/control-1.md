# AGENTS.md

OpenAgents Control (OAC) is an [OpenCode](https://opencode.ai)-based AI agent
framework: Markdown agents and subagents, context files, slash commands, a
TypeScript eval framework, a component registry, and an installer. It is not
the OpenCode codebase itself. The npm package is `@nextsystems/oac`; the
`bin/oac.js` CLI wraps `install.sh`. Current version: `0.7.1` (`VERSION`).

## Start here

- `README.md` — product overview and agent workflow.
- `.opencode/context/openagents-repo/quick-start.md` and `navigation.md` —
  two-minute repo orientation and a map of repo-specific context.
- `docs/contributing/CONTRIBUTING.md` and `docs/contributing/DEVELOPMENT.md` —
  contribution rules and development workflow.

## Commands

Prerequisites: OpenCode CLI, Node 18+, Bash, and Git; the TypeScript
validators additionally require Bun.

```bash
npm install && npm run dev:setup   # root deps + eval-framework deps
npm run dev:build                  # compile evals/framework
npm run test:openagent:core        # fast core agent tests (~5-8 min)
npm run test:ci                    # smoke tests used by CI
npm run validate:registry          # registry paths (requires Bun)
npm run validate:context-links     # context markdown links (requires Bun)
cd evals/framework && npm run validate:suites:all

./scripts/registry/auto-detect-components.sh --dry-run   # preview
./scripts/registry/auto-detect-components.sh --auto-add  # apply
./scripts/registry/validate-registry.sh
./scripts/prompts/validate-pr.sh
./install.sh --list                                       # installer smoke check
```

`npm test` runs the full eval suite; agent evals launch real OpenCode sessions,
so the OpenCode CLI and model-provider credentials must be configured. The
`Makefile` also wraps common flows: `make test-smoke`, `make test-golden`,
`make build-evals`, `make validate-evals`.

## Boundaries and conventions

- **Agent frontmatter:** use only valid OpenCode keys (`name`, `description`,
  `mode`, `temperature`, `model`, `maxSteps`, `disable`, `hidden`, `prompt`,
  `tools`, `permission`, `skills`). Put `id`, `category`, `type`, `tags`, and
  `dependencies` in `.opencode/config/agent-metadata.json`, not frontmatter.
  Use `permission:` (singular); duplicate keys and extra `---` blocks fail.
- **Canonical vs variants:** `.opencode/agent/**` is the shipped default. Keep
  PRs on the defaults and put experiments in `.opencode/prompts/**`; run
  `./scripts/prompts/validate-pr.sh` before submitting.
- **Registry:** component entries are generated by auto-detect. Do not
  hand-maintain paths; CI auto-adds for internal PRs, while fork PRs must run
  `--auto-add` and commit `registry.json`.
- **Tests are part of the change:** a new or changed agent needs matching
  config/tests under `evals/agents/...`, and suite validation must pass.
- **Context style:** MVI principle, keep files roughly under 200 lines, follow
  the existing `concepts/ guides/ lookup/ errors/` layout, and update the local
  `navigation.md` when adding files.
- **Naming and code:** kebab-case Markdown filenames, PascalCase TypeScript
  types, camelCase functions/variables. TypeScript avoids `any` and uses JSDoc;
  Bash scripts use `set -e`.
- **Commits and PRs:** PR titles must follow Conventional Commits
  (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, ...); CI enforces this and uses
  it for version bumps. PR descriptions cover What, Why, How, and Testing.
  Target `main` or `dev`.
- **Releases:** bump with `./scripts/versioning/bump-version.sh
  <alpha|beta|rc|patch|minor|major>` (keeps `VERSION` and `package.json` in
  sync), then update `CHANGELOG.md`.
- **Do not commit:** `.env`, credentials, or `.tmp/` session output (ignored;
  only curated `.tmp/` subdirectories are tracked).
